# Data dictionary: analytical model

This dictionary covers the **DuckDB analytical model** built by `scripts/build_model.py` from `sql/01_staging.sql`, `sql/02_dimensions.sql` and `sql/03_facts.sql`. Every analysis workstream and the Power BI export read from these tables.

- The **Power BI import package** (the CSVs loaded into the dashboard) has its own column-level dictionary in [`powerbi/data/data_dictionary.csv`](../powerbi/data/data_dictionary.csv). It is generated by `scripts/export_powerbi.py`.
- **DAX measures** and dashboard-only calculated columns are defined in [`powerbi/dax_measures.md`](../powerbi/dax_measures.md).
- How data moves between these layers, and how each headline figure traces back to source, is in [`docs/data_lineage.md`](data_lineage.md).

`tests/test_documentation.py` checks this file against the SQL. Every model table must have a section here, and every column listed here must exist in the SQL that builds its table. If you change the SQL, update this file in the same commit.

**Conventions**
- **Grain** is what one row represents. **Key** is the column set that is unique at that grain, enforced by a build assertion.
- **Population flags** are booleans that define who is in a KPI denominator. Rows are never deleted to define a population.
- **BA** refers to the structural build assertions in `scripts/build_model.py`. There are 34; each must return zero violations or the build fails.
- **R*n*** refers to the business rules in [`reports/project_blueprint.md`](../reports/project_blueprint.md).

## 1. Staging layer (`sql/01_staging.sql`)

These are typed copies of the nine raw Olist CSVs. Nothing is filtered, deduplicated or renamed. The raw files are read-only, and a session fixture in `tests/conftest.py` checks that they stay byte-identical.

| Table | Source file | Grain | Notes |
|---|---|---|---|
| `stg_orders` | `olist_orders_dataset.csv` | one row per order | 5 timestamps cast to TIMESTAMP |
| `stg_customers` | `olist_customers_dataset.csv` | one row per `customer_id` (one per order) | `customer_unique_id` identifies a person across orders |
| `stg_order_items` | `olist_order_items_dataset.csv` | one row per (order, item number) | an order can have many sellers |
| `stg_reviews` | `olist_order_reviews_dataset.csv` | one row per review row | some orders have 0 or more than 1 review |
| `stg_products` | `olist_products_dataset.csv` | one row per product | source column names are misspelt (`..._lenght`) |
| `stg_sellers` | `olist_sellers_dataset.csv` | one row per seller | |
| `stg_geolocation` | `olist_geolocation_dataset.csv` | one row per raw point | **not** a lookup: about 1.0M rows for about 19k ZIP prefixes |
| `stg_category_translation` | `product_category_name_translation.csv` | one row per category | Portuguese to English names |

## 2. Parameters and dimensions (`sql/02_dimensions.sql`)

### `model_params`

Grain: a single row. This is the one place where the analysis window, thresholds and reference date are defined.

| Column | Type | Definition |
|---|---|---|
| `window_start` | DATE | 2017-01-01. First purchase date in the analysis window (R2). |
| `window_end_exclusive` | DATE | 2018-09-01. The window covers purchases up to and including 2018-08. |
| `severe_late_days` | INTEGER | 7. An order is severely late if delivered more than 7 calendar days after the promised date (R10). |
| `reference_date` | DATE | The latest observed event timestamp in the extract (R9). Estimated dates are excluded because they lie in the future of the extract. |
| `geo_lat_min`, `geo_lat_max`, `geo_lng_min`, `geo_lng_max` | DOUBLE | Bounding box for Brazil, used to drop implausible geolocation points. It is wide enough to keep Fernando de Noronha. |
| `earth_radius_km` | DOUBLE | 6371.0088. Used in the haversine distance formula. |

### `dim_date`

Grain: one row per calendar day, 2016-01-01 to 2018-12-31. Key: `date_key`.

| Column | Type | Definition |
|---|---|---|
| `date_key` | DATE | Calendar date |
| `year`, `month` | INTEGER | Calendar year and month number |
| `year_month` | VARCHAR | `YYYY-MM` label |
| `month_start` | DATE | First day of the month |
| `iso_weekday`, `weekday_name` | INTEGER, VARCHAR | ISO weekday (1 = Monday) and its name |
| `is_in_window` | BOOLEAN | True if the date falls in the analysis window from `model_params` |

### `dim_state`

Grain: one row per Brazilian state (27). Key: `state_code`. This is **external reference data** (IBGE macro-regions), not derived from Olist. Verification is in `reports/data_model_validation.md`.

| Column | Type | Definition |
|---|---|---|
| `state_code` | VARCHAR | Two-letter state code (e.g. `RJ`) |
| `state_name` | VARCHAR | State name (ASCII) |
| `macro_region` | VARCHAR | North, Northeast, Central-West, Southeast or South |

### `dim_zip_geo`

Grain: one row per ZIP prefix with at least one plausible point. Key: `zip_code_prefix`.

Business rule: (1) take distinct coordinates per prefix, (2) drop points outside the `model_params` bounding box, (3) use the median latitude and longitude of what remains.

| Column | Type | Definition |
|---|---|---|
| `zip_code_prefix` | INTEGER | 5-digit ZIP prefix |
| `lat`, `lng` | DOUBLE | Median of the in-box distinct points |
| `n_distinct_points` | BIGINT | Distinct points before the bounding-box filter |
| `n_points_used` | BIGINT | Distinct points used for the median (always > 0) |

### `dim_product`

Grain: one row per product. Key: `product_id`.

| Column | Type | Definition |
|---|---|---|
| `product_id` | VARCHAR | Product id |
| `product_category_name` | VARCHAR | Portuguese category name as supplied (may be NULL) |
| `product_category` | VARCHAR | The English name; the Portuguese name if no translation exists; NULL if the category is missing |
| `is_category_missing` | BOOLEAN | Source category is NULL |
| `is_translation_missing` | BOOLEAN | A category exists but has no English translation |
| `product_name_length`, `product_description_length` | DOUBLE | Renamed from the misspelt source columns |
| `product_photos_qty`, `product_weight_g`, `product_length_cm`, `product_height_cm`, `product_width_cm` | DOUBLE | As supplied |

### `dim_seller`

Grain: one row per seller. Key: `seller_id`.

| Column | Type | Definition |
|---|---|---|
| `seller_id` | VARCHAR | Pseudonymous seller hash (as supplied by Olist) |
| `seller_zip_code_prefix`, `seller_city`, `seller_state` | | As supplied |
| `seller_macro_region` | VARCHAR | Looked up from `dim_state` |

## 3. Facts (`sql/03_facts.sql`)

Modelling rule: every one-to-many source (items, reviews) is **aggregated to order grain before** it is joined to `fact_orders`. This prevents row fan-out from inflating order counts.

### `fact_order_items`

Grain: one row per (`order_id`, `order_item_id`). Row count equals `stg_order_items` (BA).

| Column | Type | Definition |
|---|---|---|
| `order_id`, `order_item_id`, `product_id`, `seller_id` | | Keys, as supplied |
| `shipping_limit_ts` | TIMESTAMP | Seller's shipping deadline (renamed from `shipping_limit_date`) |
| `price`, `freight_value` | DOUBLE | Item price and freight, BRL |
| `product_category` | VARCHAR | From `dim_product` |
| `customer_state`, `seller_state` | VARCHAR | Destination and origin state |
| `customer_zip_prefix`, `seller_zip_prefix` | INTEGER | Destination and origin ZIP prefix |
| `is_cross_state` | BOOLEAN | Customer state differs from seller state |
| `distance_km` | DOUBLE | Haversine distance between the two ZIP-prefix centroids. This is straight-line distance, not road distance. NULL if either centroid is missing. |

### `bridge_order_seller`

Grain: one row per (`order_id`, `seller_id`). Used for validation in DuckDB only; it is not exported to Power BI.

| Column | Type | Definition |
|---|---|---|
| `order_id`, `seller_id` | VARCHAR | Keys |
| `n_items_from_seller`, `items_value_from_seller`, `freight_value_from_seller` | | Item count and value supplied by this seller in this order |
| `n_sellers_in_order` | BIGINT | Distinct sellers in the order |
| `is_single_seller` | BOOLEAN | The order has exactly one seller |

### `fact_reviews`

Grain: one row per (`order_id`, `review_id`). Row count equals `stg_reviews` (BA). There is deliberately no "latest review" flag, because in multi-review orders updates cannot be told apart from duplicates.

| Column | Type | Definition |
|---|---|---|
| `order_id`, `review_id` | VARCHAR | Keys |
| `review_score` | INTEGER | 1 to 5 stars |
| `has_comment_title`, `has_comment_message` | BOOLEAN | A free-text title or message exists. The text itself is not carried into the model. |
| `review_creation_date` | DATE | Date the review survey was sent or created |
| `review_answer_ts` | TIMESTAMP | Time the customer answered |
| `review_rows_in_order` | BIGINT | Review rows for the same order |

### `fact_orders` (core table)

Grain: one row per `order_id`. **All 99,441 orders are kept**; eligibility for each KPI is expressed through flags. Key: `order_id` (BA).

**Identifiers and dates**

| Column | Type | Definition |
|---|---|---|
| `order_id`, `customer_id`, `customer_unique_id` | VARCHAR | Keys |
| `customer_state`, `customer_zip_prefix` | | Destination |
| `order_status` | VARCHAR | Status as supplied |
| `purchase_ts`, `approved_ts`, `carrier_ts`, `delivered_customer_ts` | TIMESTAMP | Purchase, approval, handover to carrier, delivery to customer |
| `purchase_date`, `purchase_month` | DATE | Calendar date and month of purchase. `purchase_date` is the dashboard's date key. |
| `estimated_date` | DATE | Promised delivery date shown to the customer |
| `delivered_date` | DATE | Calendar date of delivery |

**Population and status**

| Column | Type | Definition |
|---|---|---|
| `in_window` | BOOLEAN | Purchased 2017-01 to 2018-08 |
| `is_delivered_dated` | BOOLEAN | Status is `delivered` **and** a delivery timestamp exists |
| `fulfilment_class` | VARCHAR | Six mutually exclusive classes (R9): `delivered_late`, `delivered_on_time`, `delivered_status_no_date`, `cancelled_unavailable`, `open_past_promise`, `open_not_yet_due`. `unclassified` must never occur (BA). |
| `has_status_date_conflict` | BOOLEAN | A delivered status with no date, or a non-delivered status with a date |

**Delivery measures** (NULL unless `is_delivered_dated`; enforced by BA)

| Column | Type | Definition |
|---|---|---|
| `lead_time_days` | DOUBLE | Delivery timestamp minus purchase timestamp, in fractional days |
| `promised_lead_days` | BIGINT | `estimated_date` minus `purchase_date`, in days |
| `promise_error_days` | BIGINT | `delivered_date` minus `estimated_date`. A positive value means late. |
| `is_late_calendar` | BOOLEAN | **Primary late flag (R1):** delivered on a later calendar date than promised. Must agree with `promise_error_days > 0` (BA). |
| `is_severe_late` | BOOLEAN | `promise_error_days` > `severe_late_days` (7) |
| `is_late_exact` | BOOLEAN | Sensitivity only. Compares exact timestamps; over-counts because the estimate is stored at midnight. |
| `days_late_band` | VARCHAR | `<=0`, `1-3`, `4-7`, `8+` |

**Data quality flags** (never NULL; anomalies are flagged, never deleted)

| Column | Type | Definition |
|---|---|---|
| `ts_sequence_violation` | BOOLEAN | Any timestamp earlier than the step it should follow (R7) |
| `carrier_leg_unreliable` | BOOLEAN | The carrier handover timestamp is out of sequence |

**Items and seller attribution**

| Column | Type | Definition |
|---|---|---|
| `n_items`, `n_sellers` | BIGINT | Item and distinct-seller counts (0 if the order has no items) |
| `is_single_seller` | BOOLEAN | `n_sellers = 1` |
| `items_value`, `freight_value` | DOUBLE | Order totals, BRL |
| `primary_seller_id`, `seller_state` | VARCHAR | Filled **only** when exactly one seller; NULL otherwise (BA). Multi-seller orders are never allocated. |
| `is_cross_state` | BOOLEAN | Seller state differs from customer state; single-seller orders only |
| `distance_km_median` | DOUBLE | Median item distance; single-seller orders only |
| `order_category` | VARCHAR | The single category if all items share one; `mixed` or `unknown` otherwise |

**Reviews**

| Column | Type | Definition |
|---|---|---|
| `review_row_count` | BIGINT | Review rows for the order (0 if none) |
| `review_score`, `review_creation_date` | | Filled **only** when exactly one review row exists (BA) |
| `review_before_delivery_flag` | BOOLEAN | The single review was created before the delivery date |

**KPI eligibility flags** (nested: seller, review and P1 populations are subsets of the delivery population; BA)

| Column | Definition | Population in window |
|---|---|---|
| `is_delivery_kpi_eligible` | `in_window AND is_delivered_dated` | 96,203 |
| `is_seller_kpi_eligible` | the above `AND n_sellers = 1` | 94,931 |
| `is_review_kpi_eligible` | delivery-eligible `AND review_row_count = 1` (P0) | 95,037 |
| `is_review_p1_eligible` | P0 minus reviews created before delivery (P1) | 90,103 |

### `v_single_seller_orders` (view)

Grain: one row per order where `is_seller_kpi_eligible` is true. Row count equals that flag's count (BA), and no multi-seller order can appear (BA). This view feeds the seller, lane and distance analyses.

Columns are a subset of `fact_orders` with these renames: `primary_seller_id` becomes `seller_id`, and `distance_km_median` becomes `distance_km`. Carried columns: `order_id`, `customer_unique_id`, `seller_state`, `customer_state`, `is_cross_state`, `purchase_date`, `purchase_month`, `estimated_date`, `n_items`, `items_value`, `freight_value`, `order_category`, `lead_time_days`, `promised_lead_days`, `promise_error_days`, `is_late_calendar`, `is_severe_late`, `is_late_exact`, `days_late_band`, `ts_sequence_violation`, `carrier_leg_unreliable`, `review_row_count`, `review_score`, `review_before_delivery_flag`.

## 4. Data quality checks

| Layer | Check | Where |
|---|---|---|
| Raw | Source CSVs byte-identical before and after every run | `tests/conftest.py` (`raw_files_unmodified`) |
| Model | 34 build assertions: grain and row counts, unique keys, referential integrity, logical invariants | `scripts/build_model.py` (`BUILD_ASSERTIONS`) |
| Model | Counts reconcile to earlier profiling anchors (e.g. 99,441 orders; 96,203 delivered in window) | `tests/anchors.py`, `tests/test_data_model.py` |

| Docs | This dictionary matches the model SQL | `tests/test_documentation.py` |

## 5. Known data limitations

- Delivery timestamps are order-level, so seller handling, carrier transit and last mile cannot be separated. The dataset has no carrier, warehouse or SLA data.
- Distance is a straight-line ZIP-prefix approximation, not road distance.
- Reviews are voluntary. Orders with several review rows have no reliable "latest" review, so they are excluded from score KPIs rather than guessed.
- Orders with several sellers (1.3% of orders) are excluded from seller results rather than allocated.

## 6. Change process

Changes to a definition (for example the late rule, the window or a threshold) are handled as follows:

1. Change the value in **one place**. Thresholds and the window live in `model_params`; there are no hard-coded copies.
2. Update this dictionary and, where the change reaches the dashboard, `powerbi/dax_measures.md`.
3. Rebuild and run `python -m pytest`. The anchors in `tests/anchors.py` are *never* edited to make a test pass. A changed anchor is a deliberate, documented decision.
4. Regenerate the affected findings reports with `analysis/build_*_report.py`, then re-check the source-to-report trace in [`docs/data_lineage.md`](data_lineage.md).
