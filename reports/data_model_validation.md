# Data Model Validation Report (Phase 1)

Generated by `scripts/build_validation_report.py` from the DuckDB model built by `scripts/build_model.py` (SQL in `sql/`). Raw CSVs in `data/raw/` are read-only and were hash-checked unchanged by the test suite. Analytical data model only: no EDA, hypothesis tests, seller rankings, dashboard or ML were performed.

Model parameters: window = purchases 2017-01-01 to before 2018-09-01 (2017-01 to 2018-08); severe lateness = promise error > 7 calendar days; reference date = 2018-10-17 (latest observed event timestamp in the extract).

The model was executed and compared with an independent pandas implementation, so correctness findings below are empirically verified; performance statements are limited to what was measured.

**Business objective.** Provide an order-grain fact (plus item, review and seller structures) from which the validated KPI populations can be computed without row multiplication.

| Severity | Finding | Evidence / status |
|---|---|---|

**KPI definitions checked.** Late rate = late / delivered-with-date in window (numerator and denominator at order grain, no divisions inside the model, so no zero-denominator path); lead time = fractional days from purchase to delivery; promise error = calendar-day difference; severe late = promise error > 7; fulfilment classes partition all orders. NULL handling: measures are NULL (not zero) when out of population; `review_score` is NULL unless exactly one review row.

**Business interpretation.** The model reproduces the established populations exactly, so it can support the planned KPIs. It does not by itself resolve the conditional-on-delivery nature of the late rate (blueprint 2.1).

## 9. Unresolved issues and limitations

- **No open order is "not yet due" in the window** (0); every open-status order in the window is past its promise at the reference date, consistent with the blueprint's hypothesis that these orders are stalled or abandoned in the data. The cause is not verified.
- **Conditional-on-delivery late rate:** unchanged from blueprint 2.1; this phase builds the populations, it does not resolve selection.
- **Time zones** of source timestamps remain undocumented; calendar-date lateness assumes dates are comparable.
- **Timestamp anomalies** (1,382 orders) are flagged, not explained.
- **Multi-review orders** (547) remain ambiguous by design; no score is assigned.
- **Anchor coverage:** anchors cover the populations and counts established in earlier reports; the window late *count* (6,531) and window review counts are new numbers verified only by the independent pandas implementation, not by a third source.
- **Provisional minimum of 20 excess late orders** (Investigate tier) is not implemented; tiers are out of scope for Phase 1.
- **External reference data:** IBGE mapping rests on one primary-source excerpt (3 regions) and one secondary source (all 5); see section 7.
- **Environment:** developed on Python 3.14, DuckDB 1.5.x, pandas 3.0.x; older versions were not tested.
- **Geography:** centroid distance is straight-line between ZIP-prefix medians, not road distance; 278 customer and 7 seller prefixes have no geolocation row in the raw file.
